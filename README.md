# ATM Cash Refill Optimizer

A data-driven dashboard that helps keep every ATM stocked with cash, right where and when it is needed. It tracks 40 ATMs across Jaipur, ranks them by refill urgency, flags unusual withdrawal behaviour, and turns the result into a daily van route plan.

Built as part of an AI-ML internship project at [InternPe](https://internpe.in).

## Features

- **Network overview**: live cash level and risk colour for every ATM, plotted on an interactive map.
- **Demand forecasting**: predicted daily withdrawals per ATM as trend lines, plus model metrics and feature importance.
- **Refill priority**: ATMs ranked by risk score, days-to-empty and recommended top-up amount.
- **Route planning**: at-risk ATMs grouped onto vans within a fixed cash capacity, with stop order and distance.
- **Anomaly detection**: unusual withdrawal amounts flagged with an anomaly score.
- **What-if prediction and comparison**: run a prediction for any ATM in the browser and compare two ATMs side by side.
- **CSV export** of the priority list.

## How it works

1. **Collect**: ATM records (zone, coordinates, capacity, minimum threshold, bank branch) and 12 months of withdrawal history.
2. **Forecast**: predict daily withdrawals per ATM from salary period, day of week, 7-day rolling average, zone type and lag features.
3. **Score risk**: days-to-empty is `current cash / forecast daily withdrawal`. Risk score bands: under 1 day is 85-100, 1-2 days is 65-80, 2-4 days is 40-60, beyond that 30 or less.
4. **Recommend**: an ATM needs a refill when its cash falls below its minimum threshold. The suggested top-up is `capacity - current cash`.
5. **Plan routes**: refill ATMs are grouped onto vans (capacity 5,000,000 per van) starting from the Central Cash Vault (C-Scheme). Distances use the Haversine formula, with estimated time of 0.4 h per stop plus travel at 40 km/h.

### Model performance

| Metric | Value |
|---|---|
| R² | 0.77 |
| MAPE | 12.77% |
| MAE | ₹37,498 |
| Training samples | 3,320 |
| ATMs | 40 |
| Anomalies detected | 15 |

> The forecasting model was trained offline. Its output (forecasts, priority, routes, metrics) is stored in `backend/atm_data.json` and seeded into SQLite by `init-db.js`. The backend serves this data and does not retrain the model.

## Database schema

| Table | Purpose |
|---|---|
| `atms` | ATM master data: zone, zone type, lat/lon, capacity, min threshold, bank branch |
| `forecasts` | Predicted withdrawal per ATM per date |
| `anomalies` | Flagged withdrawals with anomaly score |
| `priority` | Current cash, capacity ratio, days-to-empty, risk score, refill flag, recommended fill |
| `route_plans` | One row per generated plan: vans, ATMs, cash, distance, van capacity, depot |
| `van_stops` | Ordered stops for each van in a plan |
| `model_metrics` | MAE, MAPE, R², training samples, ATM count, anomaly count |
| `feature_importance` | Importance score per feature for a metrics run |

Relationships: `atms` 1-* `forecasts`, `anomalies`, `van_stops`; `atms` 1-1 `priority`; `route_plans` 1-* `van_stops`; `model_metrics` 1-* `feature_importance`.

## API endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/atms` | All ATMs |
| GET | `/api/atms/:atmId` | Single ATM |
| GET | `/api/forecasts` | Forecasts for all ATMs |
| GET | `/api/forecasts/:atmId` | Forecast for one ATM |
| GET | `/api/priority?sort=risk_score` | ATMs with risk data (sort by `risk_score`, `days_to_empty`, `current_cash`, `recommended_fill_amount`; optional `order=ASC\|DESC`) |
| GET | `/api/anomalies` | Flagged anomalies |
| GET | `/api/routes` | Latest van route plan with per-van distance and time |
| GET | `/api/metrics` | Model metrics and feature importance |
| PATCH | `/api/atms/:atmId/cash` | Update an ATM's current cash and recalculate its risk metrics |
| POST | `/api/priority/recalculate` | Refreshes the `last_updated` timestamp on priority rows |
| GET | `/api/health` | Health check |

## Getting started

### Prerequisites

- [Node.js](https://nodejs.org) 18 or later
- npm

### 1. Clone the repository

```bash
git clone https://github.com/darshilsaboo1401/Atm-cash-Prediction.git
cd Atm-cash-Prediction
```

### 2. Start the backend

```bash
cd backend
npm install
npm run init-db    # creates atm_optimizer.db and seeds it from atm_data.json
npm start          # API on http://localhost:5000
```

Run `npm run init-db` once. Running it again inserts anomalies, route plans and metrics a second time.

Check that it works: open <http://localhost:5000/api/health>.

### 3. Start the frontend

In a second terminal:

```bash
cd my-app
npm install
npm start          # dashboard on http://localhost:3000
```

The frontend calls `http://localhost:5000/api` by default. To use a different backend, set `REACT_APP_API_BASE` before starting.
